# 07 — Deployment, zero-cost operations and recovery

## 1. Free cloud stack decision
Use Cloudflare Workers Free (100k requests/day, CPU 10ms/request, 5 cron triggers/account per public limits); Supabase Free (500MB DB, 50k MAU, 5GB egress + cached egress, 1GB storage; paused after 1 week inactivity; no automated backups/PITR included); Resend free forever (verify current monthly quota and max 100/day, sender domain); Workers AI 10k neurons/day for free-eligible models. All quotas snapshot 27/11/2026; re-check before deployment. One user, conservative limits, no uptime guarantees. No paid hosting or self-host. Existing domain registration/renewal, device Internet, electricity, paid AI, optional bank fees excluded from zero-cost promise. Cloudflare D1 free is alternative if PostgreSQL/Auth limitations change; not interchangeable without migration. Neon free alternative DB, requires separate auth integration. Supabase best balance of transactional SQL+Auth+SMTP with one managed project. No paid Supabase custom domain; use default project endpoint internally.

## 2. Operator deployment checklist (one-time, before wizard)
1. Cloudflare account: confirm domain DNS active and free Workers plan. Decide subdomain `api.example.com`; use Worker Custom Domain per dashboard, HTTPS automatically provisioned. No Tunnel or port forwarding, no VPS. Reserve optional `app.example.com` for verified app links/recovery landing (Worker static asset route). Do not alter existing MX/site records.
2. Supabase: create Free project in nearest available region, choose strong DB password in password manager, keep project URL and publishable key, never commit DB password. Apply reviewed migrations using Supabase CLI or SQL editor. Enable RLS, revoke public table/RPC access, verify direct anon/auth access denied. Auth settings: email/password on, disable public signups, disable unused providers, configure token TTL, minimum 12-char password as supported; allowed redirect URLs exact HTTPS recovery/invite path, not wildcard; test SDK flow and email confirmation. Enable platform MFA for operator accounts. Create private bucket `receipts` only if needed; restrict access to Worker signed URLs, max files/size.
3. Resend: create free account, add sender subdomain e.g. `mail.example.com`, add SPF/DKIM verification DNS records as provider gives (DNS-only when required), DMARC policy review, avoid conflicting SPF. Verify domain. Generate restricted send key; set Supabase Auth custom SMTP using current Resend SMTP docs (host/port/user exact documented, key as password); from `finance@mail.example.com`. Disable email link tracking to avoid altering auth links; test invite/recovery with actual owner email. SendGrid alternative SMTP only if already funded/eligible; no paid failover. Do not send login password in email. Auth template Vietnamese, clear expiry, ignore if not requested, link target exact domain. Rate limit recovery/invite. Resend account cap check; if no email delivered, wizard cannot complete without operator recovery; no insecure bypass.
4. Worker: create code with `wrangler` and `config/wrangler.example.toml` adapted to actual domain/account. Deploy staging on separate environment using mock data (Supabase free allows limited projects). Set secret values via `wrangler secret put` or dashboard, never commit .dev.vars; configure public project URL, owner expected email as secret, bootstrap secret ≥32 random bytes, service role, encryption secret if needed, provider webhook/API secrets only after approved POC, optional AI keys. Bind Workers AI only if free-eligible and privacy approved. Deploy free plan, configure custom domain and cron. Use `GET /v1/health` verify minimal status; test auth and DB connectivity in private diagnostics.
5. Android: choose unique app package ID owned by user, generate signing key offline (backup securely), never commit keystore/password. Configure app build base HTTPS API domain, Supabase public URL/key (or fetch verified config from API), Android App Links for invite/recovery using `/.well-known/assetlinks.json` with real package + SHA256 signing cert; validate `adb shell pm get-app-links` on device. Recovery landing page no token logging, Referrer-Policy no-referrer, no analytics, no external resources. Test invite PKCE/code/token flow per SDK; avoid link scanner consuming single-use links by appropriate confirmation interstitial. Build signed APK; sideload from trusted artifact or Play distribution (Play developer registration can cost money, not required). Keep app signing key stable for upgrades. No hard-coded secrets in APK.
6. First setup: operator configures fixed owner email and one-time secret, opens app and follows wizard W00–W13. After owner binding remove/rotate bootstrap secret, verify second setup denied; disable debug/demo endpoints. Configure Notification allowlist and test on actual device. API integrations default off until no unintended billing and real data proven. AI free/off default; if paid set direct API key, prepaid small balance, no auto-top-up and explicit cap.
7. Run acceptance tests and record deployment evidence (date, SDK/API versions, real source capability, quota, observed errors); do not claim coverage on unsupported sources.

## 3. Configuration / secrets
Public config: API version, display name, timezone, locale, auth project URL, publishable key, capability registry version, max batch sizes. Secrets: SUPABASE_SERVICE_ROLE_KEY, OWNER_EMAIL, BOOTSTRAP_SECRET (remove after bind), PROVIDER_SEPAY_API_KEY / WEBHOOK_SECRET if enabled, DEEPSEEK_API_KEY, GEMINI_API_KEY optional, BACKUP_ENCRYPTION_KEY optional only for server-held backup (prefer client encryption). Supabase SMTP key set in Supabase dashboard, not Worker. No arbitrary credentials supplied via app. Use separate prod/dev project; redact logs; rotate keys and revoke connections on incident. Operator login MFA.

## 4. Cost controls
| Resource | Soft alert | Action at limit |
|---|---|---|
| Cloudflare Worker requests | 80% of plan | stop optional polling, batch requests, core error/offline; no upgrade |
| Worker CPU | observed repeated limit error | reduce batch, move logic to SQL, no paid plan |
| Supabase DB | 350MB alert, 400MB prune safe raw | export first, purge expired sanitized events/AI logs only, refuse big attachments; ledger retained |
| Supabase storage/egress | 70–80% | compress local OCR, limit receipt upload, local only, no paid add-on |
| Resend | 80% daily/monthly | throttle optional mail; preserve recovery attempts where possible; no paid fallback |
| SePay | verify hard stop at provider | default disabled if no hard cap; local stop does not prevent provider billing; upstream pause/disconnect verified |
| AI free | 80% of available quota | fallback Rule Engine, no paid switch |
| AI paid | 80% cap | reserve and block at cap, prepaid/no auto-top-up, no background model upgrade |

Conservative batch/read windows: default poll every 15 min when enabled, overlap <=48h, page size <=100, bounded jobs. Raw sanitized evidence retention 90 days by default once linked; keep canonical transaction, source ID/hash, evidence provenance, unresolved events; audit critical financial changes indefinitely or export. AI proposal expiry 15min, logs usage 12mo aggregate only; optional chat history off default, purge on request. Attachments 2MB each after compression, max 100MB total default; store private. No cron keepalive abuse; free project may pause naturally, user resumes in dashboard. Budget assumptions may change with free provider policies.

## 5. Backup & recovery
Supabase Free not relied on for automated backup. App weekly reminder export encrypted archive (JSON manifest/schema version, accounts, journals/entries, canonical transactions, debt/goals/budget/rules, provenance and config without secrets; optionally attachments). Client encrypt with vetted AES-256-GCM, random nonce per file, key from passphrase via memory-hard KDF with documented params, checksum manifest; use OS Storage Access Framework to save to user-controlled storage. Never upload plaintext export. Export paginated consistent snapshot using as-of sequence, no huge Worker CPU; optional operator `pg_dump` from laptop on demand via supported connection; this is backup task, not self-host. Restore preview validates schema/version, checksums, ledger sums, owner mapping, counts, duplicate keys; fresh deployment restore with auth owner already set, map IDs deterministically, never restore secrets or auth password hashes through app. Operator import in bounded transactions/staging, validate before activation; no merge-overwrite default. Test restore with synthetic data before relying on backup. RPO weekly if user exports; no guarantee; remind on missed backup. RTO manual within a day target.

## 6. Runbook
| Incident | Response |
|---|---|
| Supabase paused/unavailable | show offline/stale, retain device outbox; resume project dashboard, verify auth/schema, replay queue, poll/reconcile gap; no fake success |
| Worker quota reached | disable optional cron/poll, wait reset; preserve offline queue; if webhook missed, provider backfill/statement |
| Provider auth expired | state AUTH_REQUIRED, stop sync, official relink, record gap, bounded backfill |
| Provider unexpected fee | pause upstream via documented action or provider dashboard, verify billing, disconnect if needed, review charge; don't just toggle app |
| Notification permission revoked | show permission status on resume, guide OS settings, import missing period; no silent bypass |
| Duplicate booked | review evidence, reverse duplicate journal atomically, rerun report; never delete history |
| Balance mismatch | compare same basis/as-of, look for gap/transfer/fees, import statement, explicit adjustment if confirmed |
| AI quota/model failure | switch rules/manual, mark failed proposal; no booking from invalid output |
| Lost phone | revoke device/refresh sessions, rotate if needed, log in new device; pending local-only events may be lost, reconcile |
| Secret leak | disable affected routes, rotate secrets, revoke provider and sessions, audit without logging PII, rebuild |
| Email delivery failure | verify sender DNS/SMTP/rate limit, check Resend delivery, retry invite/recovery; operator recovery via console only |
